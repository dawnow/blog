## 想法

今天中午午飯過後花了兩個半小時去把我的個人博客同時部署到 Coding 託管平台，之前只把代碼放在了 Github，之所以這樣做是因為 Github 的服務器在國外，這樣會使國內某些地區的用户訪問不了，而 Coding 去年已經把主機放在騰訊雲了，因此國內網絡環境下訪問解析到 Coding，境外網絡環境下訪問解析到 Github，這樣**加載速度會有顯著提升。**

## 試錯

上午走路時萌生這個想法，飯後就開始打開瀏覽器**註冊、Google、試錯、解決問題、等待、又出錯再去搜尋解決辦法**，試錯的過程肯定是**反覆的**，中間確實有點想放棄了，有些問題網上可以搜索得到，有些問題由於版本的差異網上也沒有，別人的解決辦法反而會因為年代久遠而把你帶溝裏，這時候你就得動腦筋了，反覆嘗試，最終在兩點半的時候網頁渲染已經好了，就差自定義域名並申請證書了。又出了點小差錯，網頁安全證書申請失敗，這意味着當你打開這個網頁後會提示「**你打開的網站缺乏安全證書**」諸如此類的話，好在網上有解決辦法，在暫停了另一個倉庫的 DNS 解析並等待了 30 分鐘後重新申請了一次（30 分鐘內只能申請一次，中間小睡了一會兒），終於可以正常訪問了。

## 意外

由於期間我甚至錯到差點把原來 Github 上正常的部分給弄沒掉，因此頻繁進去 Github 的 Setting 選項，等待的時候就在 Github 上面逛了起來，隨便一搜，搜到了 **OpenJMU** 的項目，突然驚訝，啊！這不是我們學校的 App 嗎，看了看，賬户裏面有 **7 個倉庫**，OpenJMU 目前有  **94 顆 ** ⭐了，打開 README 文件看了看，又點進官網一看，瞭解了一些東西。

## OpenJMU

這是 OpenJMU Team 使用 **Flutter** 對「**集大通**」[^1]進行重寫的客户端。但是我還不知道這個團隊是由我校學生組成的還是由外部專業全職人員組成的（也有可能是校友）。這個 Github 地址的 README 文件裏面對很多問題都做了解釋。包括以下方面：

[^1]: 這是我們學校的舊版官方 App

### 為什麼用 Flutter？ Why Flutter ?

Flutter 是一套跨平台開發框架，能很好的在接口完備的情況下快速構建所需功能，只需負責 UI 邏輯層。

### 為什麼要重寫？ Why needs to rebuild ?

- 原本的應用為外包公司製作，由於學校網絡建設策略的原因已經停止維護。應用在各平台上均有大大小小的問題，影響到用户的正常使用。

- 更新應用能讓師生羣體均獲得更好的應用體驗，同時可以擴展新功能。

我不知道這算不算是一個**官方支持的民間項目**？總之這個軟件的開發者值得尊敬。用讚美和鼓勵來代替嘲諷和謾罵，事情往往會往好的方向發展。全世界 70 億人，只有大約 0.33% 的人懂得怎麼寫代碼。[^2]
